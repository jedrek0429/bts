# BTS 0.3 release audit and hardware gate

This audit covers every open issue carrying `release/0.3.0`, every open child of the four 0.3 milestones, the corrective release tracker, and #89 because #118 explicitly makes it part of the 0.3 completion gate despite its later `release/0.4.0` label. It describes the final corrective stack based on `release/0.3.x`; it does not claim that unmerged work is present on the release branch.

Status vocabulary:

- **Implemented and verified**: every deterministic criterion is represented by code, documentation and automated tests.
- **Implemented; hardware gate remains**: deterministic criteria are covered and the finite manual check is listed below.
- **Superseded and verified**: the original spelling or architecture was replaced deliberately before 0.3 stabilisation, while its required observable behaviour remains covered.
- **Tracker complete after child closure**: the tracker has no independent software requirement once its audited children are closed.

## Finite human release-gate checklist

All deterministic checks must be green before starting this list. Record the host image, architecture and exact commit/RC asset for each run.

- [ ] On a clean Debian-family ARM64 Raspberry Pi, verify the architecture-specific `bts-install-linux-aarch64` checksum, execute it, install Display-only without a repository or Rust toolchain, and confirm no manual `seat` group or `/usr/bin/seatd` compatibility link is needed.
- [ ] On that Display host, verify tty1 takeover, seatd/Cage/DRM/Wayland start-up, Cabin rendering, hidden cursor, input access and clean tty/getty restoration after Display removal.
- [ ] Connect two physical Displays with distinct stable IDs to a remote Core; verify independent Clock/Weather state, targeted Clear remaining blank for more than one clock refresh interval, an explicit later Clock action restoring only its target, and reconnect after real network/Core interruption without duplicate identity.
- [ ] On a supported Arch Display host, verify installation never invokes an AUR Cabin package and that the bundled Cabin font renders; removal must not delete an administrator-owned font.
- [ ] On the Telephony host, use an Asterisk parent with `0750 asterisk:asterisk`; install/upgrade Telephony and verify the service identity traverses the configured path, writes only `bts-generated`, unrelated Asterisk state remains protected, `doctor` reports the same result as the service identity, and rerunning reconciliation is idempotent.
- [ ] Against the deployed Kokoro service, verify `doctor` accepts its real streamed/chunked WAV response, Telephony warms all static speech before readiness, the first call has no synthesis pause, and a deliberately uncached dynamic prompt follows the documented error-tone/background-warm fallback without a late enqueue after hang-up.
- [ ] With a real telephone and audio path, verify the manifest-driven menu actions (`2` Clock, `3` Weather, `4` Clear), global `0` configuration, `*` cancel/back and `#` confirm; change between a terminal, group and all-target during a call and confirm existing screens do not change until a later explicit action.
- [ ] On clean supported Debian and Arch test hosts, inject a late service-start failure during install and upgrade; verify BTS-owned configuration, units, activation links, installer state, generated-sound namespace and tty/service state roll back, a second rollback/recovery is harmless, rerun succeeds, and package/account changes are reported as outside the atomic boundary.
- [ ] After the human publishes the next RC, inspect its manifest, `SHA256SUMS`, licence, x86_64/aarch64 component bundles, architecture-specific installers and legacy x86_64 installer alias; execute self-update on both x86_64 and ARM64 and confirm neither architecture can select the other's binary.
