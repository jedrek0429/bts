# BTS Design Standard

Version 1.0

This document defines the visual and behavioural standards for all Bansleben Telephone Services software. All services should present a consistent experience regardless of platform or purpose.

Where a decision is not explicitly covered by this document, preference should be given to clarity, consistency and simplicity.

---

# Principles

## Information comes first.

The purpose of every interface is to present information or allow an action to be completed.

Decoration must never reduce legibility or slow interaction.

## The system should remain calm.

BTS should never feel busy or distracting.

Movement, colour and sound should always serve a purpose.

## The system should respond immediately.

User actions should produce an immediate result.

Interfaces should never feel animated for the sake of animation.

## Consistency is more important than novelty.

If two services perform similar tasks, they should present information in the same way.

Users should never have to learn different behaviours for different parts of the system.

---

# Typography

The primary typeface is Cabin.

The typeface shall be used throughout all interfaces unless a technical limitation prevents it.

Bold text should generally be avoided.

Hierarchy should be established through spacing, alignment and size rather than weight.

Numbers should use tabular figures where available.

---

# Colour

The interface consists of four colours only.

Background

    #000000

Primary text

    #FFFFFF

Secondary text

    #909090

Accent

    #FFB000

The accent colour should indicate the current point of focus or the current state.

It should not be used for decoration.

Additional colours should only be introduced where required to convey meaning, such as safety warnings or camera feeds.

---

# Layout

All interfaces should align to a consistent grid.

Whitespace should be considered part of the layout.

Elements should never appear crowded.

Content should remain centred or aligned according to the service's purpose.

Margins should remain consistent across services.

---

# Motion

Screen changes shall be instantaneous.

Interfaces should never transition between screens.

Movement is reserved for changing information.

Acceptable examples include:

- clocks
- scrolling text where required
- progress indicators
- live status updates

Decorative animation should not be used.

---

# Language

All user-facing language should use natural British English.

The tone should be:

- polite
- direct
- informative
- calm

Avoid unnecessary enthusiasm.

Avoid humour unless explicitly appropriate to the service.

Avoid technical terminology where ordinary language is sufficient.

For example:

Good

    Weather information is currently unavailable.

Better than

    Error loading weather.

Good

    Connection established.

Better than

    Connected!

---

# Information hierarchy

The most important information should be immediately visible.

A user should understand any screen within approximately one second.

Where additional information is required, it should appear beneath the primary information rather than replacing it.

---

# Interaction

Every interaction should feel deliberate.

Selecting an option should immediately display the requested service.

Confirmation should only be requested where an action cannot easily be undone.

---

# Services

All applications are referred to as services.

Examples include:

- Weather Service
- Music Service
- Camera Service
- Conversation Service

The user interacts with BTS as a single system rather than a collection of separate applications.

---

# Sound

Audio should be clear and restrained.

Voice prompts should be spoken at a measured pace.

The system should acknowledge requests without unnecessary commentary.

Notification sounds should be brief and unobtrusive.

---

# Accessibility

All interfaces should remain readable from several metres away.

Important information should never rely solely upon colour.

Interfaces should remain usable without sound.

---

# Performance

Services should appear immediately after selection.

Visual updates should occur without noticeable delay.

Where information must be retrieved, the interface should remain responsive and clearly indicate that retrieval is in progress.

---

# Identity

The identity of BTS is established through consistency rather than branding.

Interfaces should be recognisable through their typography, spacing, language and behaviour rather than logos or decorative graphics.

The system should feel dependable, organised and considered.
